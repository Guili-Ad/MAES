## 已确认缺口与改动

1. 正常画面每250 ms进入暂停OCR。最后一轮全曲505次，单次P50约53 ms、P95约59 ms；全循环P95约166 ms，截图P95约29 ms，问题不只是截图。增加当前暂停界面的廉价负向预筛；白色面板或绿色标题任一可疑仍跑原OCR。黑屏、未知格式/分辨率保留OCR；启动、恢复和严格结束规则不变。
2. 未进入20 ms冻结区的纯点按也可能等待80–90 ms，期间不取图。生产循环点按等待预算改用已有45 ms截图保护值，让更远事件取得新画面。没有移动截止时间、提前量或分组冻结规则；混合长按的原执行窗口保留。
3. 健康普通点按的轮廓短时完全重复，可能丢失原身份。保留原轨迹的短时精确轮廓所有权，重复轮廓不作为新的速度样本；恢复运动仍可关联。长按、绿星、划动和静态HUD不走该规则，不增加位置屏蔽或连打冷却。
4. 从86 px轮廓缩成18 px碎片的两帧轨迹仍可coast，产生迟到补点。增加面积连续性检查。录像2约30.5秒右侧同轨连打出现Miss；实战轨迹174保留早期截止时间，之后轨迹180又产生输入。逐帧回放另复现碎片造成的额外点按，本轮已消除该回放中的一次重复。
5. 划动关联只检查“是否划动”，不检查颜色方向一致性，红色左划可接到蓝色背景部件。新增方向一致性检查，不改变划动距离、时长、同步输入或长按尾端策略。录像5约38.5秒左划Miss，日志有同侧Tap和明显偏后的FlickLeft；跨色接管是已复现漏洞，但不能断言是该Miss的唯一原因。

诊断新增每次运行自己的全曲指标、清理结果、非点按排队/预测修正及实际输入时的最新观测。原music_last_result仅保存最后一轮，不能代表前7轮。新记录仍以内存缓冲为主，结束写盘，截断显式报告；主机调用时间不是游戏判定时间。
