# 剩余失误小范围修复验证

## 验证定义

基线`75e0f86`，候选`v1.0.6-residual-candidate`。没有连接游戏控制器，没有取得新包实战成绩。旧591项有效测试保留，完整630项通过；新增用例不能把“主机调用成功”当成游戏Perfect，也不能把“输入减少”当成准确删除假音符。

本轮包含两类不同的录像验证，不能混用：

1. 固定PTS性能：10个窗口共1800个压缩视频帧，归一化1280×720；每帧都消费一次。基线／候选独立模块、跟踪器、队列和模拟时钟，使用相同像素、候选、配置和校准。输入传输瞬时模拟，不能验证实际划动持续时间。
2. 完整前导生产循环：每个窗口从原视频PTS零开始，包含此前头部、白带及尾部；调用实际`MusicRuntime.play`及同步交错输入，通过模拟阶段成本选取截图。动作改变会改变截图相位，因此不能按第几个事件硬对齐。NumPy、视频压缩和注入的全曲阶段成本中位数都与实战Maa逐帧成本不同。

## 性能过程必须保留

最初分进程顺序运行的性能结果随整机速度明显改变，包括未修改的掩码／候选阶段也一起快慢变化。`final-*`、`optimized-*`、`delivery-*`及其他失败报告均保留，不能挑选先前较快的候选测量代替最终准入。

随后使用`tools/residual_paired_pts.py`在同进程紧邻处理同一帧，并逐帧交替先运行的实现；模块切换和视频解码在计时之外，不修改操作系统电源设置、不关闭用户程序，也不跨帧缓存视觉结论。独立源码图的实际导入路径、同帧顺序及输入摘要均有检查。

首轮交替测量的资格增量均低于2ms；额外整帧保守检查在熊熊混合段为+2.516ms，因此没有标为完整通过。补充未Down身份保护后，对冻结的最终源码预先固定三轮全部十个窗口，三轮所有样本联合计算P95，仍要求资格、资格＋规划＋派发及整帧三种增量均不超过2ms。单轮数据和失败项没有丢弃；单轮仍可能略超标，不声明每个轮次均通过。

## 混合输入的实际发现

- 觉醒窗口原模拟基线存在最后有效观测已陈旧约1.83秒的划动，候选拒绝；目标三次金圈仍有完整输入。录像已知的164／181ms迟到并未在固定中位数成本回放中完整复现，不能声称它们已经取得游戏Perfect。
- 灵魂114秒附近另有最后观测已陈旧约1.6秒、画面没有对应箭头的旧划动被拒绝。全力原日志2.947秒陈旧划动未在目标回放中复现，自动化回归另覆盖长时间陈旧输入。
- 初版划动资格在熊熊目标窗少了一条真实右划。88.14秒实际画面确认箭头存在，不能把它列入假输入清单。单独检查点`e2eb4bd`消除“新截图已取得，却先检查独立划动旧资格”的顺序错误。回归先在旧顺序失败，再验证每帧先观察且只观察一次，观测年龄／冻结／deadline均不变。专项完整前导恢复窗口三次划动。

## 保护性契约与交付状态

独立进程健康动作契约`final-contract-sealed.json`覆盖66项旧持续模式测试、50条旧持续动作、5条健康金圈动作、四类点按及两种双划动到期间距；数量、顺序、坐标和deadline一致，截止偏差0ms（上限0.1ms）。另有真实移动箭头观测的双划动Down／Move／Up对照。它们是固定健康输入保护，不等于证明所有录像真实动作均无回归。
